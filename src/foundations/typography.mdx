# Typography

Typography in this design system is a set of **semantic roles**, not a collection of font sizes. Each role describes the purpose of a piece of text. The size, weight, font and line height follow from that role.

The system is built for a dense admin panel: the default text size is 14px (`body.md`), and only a few styles change between mobile and desktop.

## How to pick a style

- First, ask what the text is for: a page title, a card title, a button, help text, a typed value?
- Then pick the role that matches that purpose.
- Pick the size (`lg`, `md` or `sm`) that fits its place in the hierarchy.
- Apply the style as-is, without overriding size or weight.

If a role feels too big or too small somewhere, reconsider the purpose of the text instead of overriding the style.

## Naming

A text style is named `{role}.{size}.{emphasis}`. In code, the dots become dashes, the class is prefixed with `type-`, and the `base` emphasis is left out:

- `body.md.base` is `type-body-md`
- `body.md.strong` is `type-body-md-strong`

Only body and caption have a `strong` emphasis, because strong is only for running text. See [Strong is only for running text](#strong-is-only-for-running-text) for when to use it.

Names describe the purpose and never the visual value. `body.md` stays `body.md` even if it changes from 14px to 13px.

The `type-` prefix avoids a clash with Tailwind's `text-*` classes, which are already used for both size and color.

## Roles

## Responsive modes

The system has two modes: **mobile**, the default, and **desktop**, from the `lg` breakpoint (1024px). Tablets use the desktop mode because admins use desktop layouts on tablets.

Only three roles change between modes:

- **Display** and **headline** step one Tailwind size smaller on mobile.
- **Input** is 16px on mobile and 14px on desktop. iOS Safari zooms into inputs with text smaller than 16px when they get focus.

All other roles keep the same size everywhere, so components behave the same on every screen. Text styles contain no responsive logic themselves. The modes switch the underlying tokens, and every style follows automatically.

An iPad in landscape is wider than 1024px, so it gets the desktop mode and 14px inputs.

## Tokens

The text styles are built from three layers, all defined in `src/theme.css`:

- **Primitives** are Tailwind's default scale: `--text-sm`, `--font-weight-medium`, `--tracking-tight` and so on. They are never changed.
- **Semantic tokens** point at primitives, per role and per size:
  - `--type-body-font`, `--type-body-weight-base`, `--type-body-weight-strong`, `--type-body-tracking`
  - `--type-body-md-size`, `--type-body-md-line-height`
- **Text styles** are the `type-*` utilities. They only reference semantic tokens.

To change the typography of the whole admin panel, change a semantic token. For example, pointing `--type-body-md-size` at a different primitive changes every component that uses `body.md`. Never change the primitives, and never add sizes outside Tailwind's default scale.

## Rules

- **Typography and color are separate.** A `type-*` class sets typography only. Color comes from its own class, such as `text-mauve-600`. There are no styles like `caption-muted` or `label-danger`.
- **Components own their typography.** `Button`, `Label`, `Input`, `Field` and `Error` already apply the right style. Write a `type-*` class directly only for free-form content inside a page.
- **No raw font classes.** Components never use `text-sm`, `font-medium` or `font-heading` directly.
- **No overrides.** Don't use `DANGEROUS_className` to change the size or weight of a component's text. Pick a different role or size instead.
- **Strong is only for running text.**<span id="strong-is-only-for-running-text" /> Use `strong` to emphasize part of a sentence, such as the customer name in a
  table row ("**Jane Cooper** placed an order") or a key fact in a caption
  ("Ships **tomorrow**"). That's why only body and caption have it. Display,
  headline, title and label are single names where the whole text is one unit:
  to make one stand out more, use a different role or size. Mono values are read
  character by character, so emphasis doesn't help there either.
- **Selected states aren't strong.** Don't make an active tab or nav item bold: bolder text is wider and shifts the layout. Use color or an indicator in the component instead.
- **Use only the sizes that exist.** Some roles deliberately have no `sm` or `lg`. Don't borrow a size from another role to fill the gap.

## Components

- `Button` uses `label.md`.
- `Label` uses `label.md`, and its "(Optional)" marker uses `caption.lg`.
- `Input` uses `input.md`.
- `Field` descriptions and `Error` use `caption.lg`.
