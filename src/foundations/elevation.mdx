# Elevation

Elevation shows how far a piece of UI sits above the page and what covers what. Like typography, it is a set of **semantic roles**: a component picks the plane that matches its purpose, and its background, border and shadow follow from that plane.

Elevation is two separate things:

- **Depth** is how a plane looks: its background, border and shadow. It comes from the plane.
- **Stacking** is what paints on top of what: the z-index. It comes from the layer the element lives in, and inside the popup layer, from the order things opened in.

Never use one to fix the other. A higher z-index doesn't make something more important, and a bigger shadow doesn't bring something to the front.

## How to pick a plane

- First, ask whether the element is part of the page or floats above it.
- If it is part of the page, use **surface**, or **sunken** for a quiet tint. Use **raised** only while the page moves under it.
- If it floats, ask whether it blocks the page. A menu or select doesn't: **popover**. A dialog or drawer does: **overlay** below **elevated**.
- Use the lowest plane that works. If something feels too flat, fix spacing and grouping first.

## Layers

Layers decide what covers what. Each has a z-index token, and there are no other z-index values in the app.

### The popup layer

`theme.css` puts every Base UI portal (`[data-base-ui-portal]`) on the popup layer and pins it to the top left of the page. Each portal is its own stacking context, so:

- **Later covers earlier.** A dialog or menu opened later covers the ones opened before it, backdrop included.
- **Nested goes on top.** A portal opened from inside another one, such as a menu in a dialog, is nested in it after its popup, so it ends up on top without any z-index.
- **No z-index inside a portal.** The backdrop comes before its popup in the DOM, so it stays below it. Positioners, popups, backdrops and toast viewports set no z-index.

### Local stacking

Some components overlap their own parts: the buttons of a ButtonGroup share a border, and a row's actions sit above the link stretched over the row. That stacking must never leak into the page, where `z-10` would paint over a sticky bar.

Put `isolate` on the component's root, so it becomes its own stacking context, and lift the part with `z-1`.

## Scenarios

The admin panel combines planes and layers in a few recurring ways.

- **A menu or select inside a dialog.** Its portal nests in the dialog's, so it opens above it. Nothing to do.
- **A confirmation over a dialog or drawer.** **One scrim at a time**, so the page isn't dimmed twice. Opened from inside the dialog, it is nested, and Base UI renders no backdrop for it. Opened from elsewhere, in its own portal, it brings its own scrim: mark every scrim with `data-overlay`, and it fades out while a scrim in a later portal is open. Dialog and AlertDialog already do.
- **A drawer below the mobile nav.** Start the scrim and the panel below the nav, so the nav stays visible and usable. The drawer is elevated: border on its inner edge, `shadow-elevated`.
- **Toasts and a docked bar.** The unsaved changes bar is on the docked layer, toasts on the popup layer above it. `useToastPosition` moves the toasts above the bar, so they don't cover each other.
- **A full-screen takeover.** The image lightbox covers the whole viewport, so it has no edges to separate: it uses `bg-canvas` and no border, shadow or scrim.
- **Dragging.** The dragged item is temporarily raised (`shadow-raised`, `z-1` inside its isolated list or in a portal) and returns to its resting plane on drop. Its old place is shown in `bg-sunken`.
- **Sticky headers.** A sticky bar is on the sticky layer. It is raised only while content scrolls under it; at the top of the page, it is a surface.

## Interaction

- **Hover, press and focus** never change the elevation. Use color, such as `hover:bg-mauve-100`, and the focus ring.
- **Opening a non-blocking popup** shows a popover; the page stays usable.
- **Opening a blocking popup** shows the overlay and the elevated plane together. They always close together, which Base UI does by keeping them in one portal.
- **Dragging** raises the item until it is dropped.

## Dark mode

Shadows barely show on dark backgrounds, so in dark mode:

- Higher planes are lighter: the canvas is `mauve-950`, surfaces and elevated planes are `mauve-900`, sunken is halfway between.
- The shadow color is 40% black instead of 10%.
- The scrim is 60% black instead of 40% `mauve-950`.

Components don't need `dark:` variants for any of this: the tokens switch with the `.dark` class.

## Accessibility

A shadow is never the only boundary of a plane. Even the strongest shadow, 10% black on white, is far below the 3:1 contrast WCAG 1.4.11 asks of a boundary that identifies a component. So every plane above the canvas that has the same background as the plane below it carries `border border-border`. The border marks the edge; the shadow only shows depth.

## Tokens

Elevation is built from three layers, all defined in `src/theme.css`:

- **Primitives** are Tailwind's colors (`--color-white`, `--color-mauve-*`, `--color-black`), its blur scale and the geometry of its `shadow-sm`, `-md` and `-lg`. They are never changed.
- **Semantic tokens** point at primitives, per plane and per layer:
  - Backgrounds: `--color-canvas`, `--color-sunken`, `--color-surface`, `--color-elevated`, `--color-overlay`
  - Scrim blur: `--blur-overlay`
  - Shadows: `--shadow-raised`, `--shadow-popover`, `--shadow-elevated`, all colored by `--color-elevation-shadow`
  - Layers: `--z-index-sticky`, `--z-index-docked`, `--z-index-popup`, `--z-index-skip-link`
- **Classes** are the Tailwind utilities generated from them: `bg-surface`, `shadow-popover`, `backdrop-blur-overlay`, `z-docked` and so on.

To change the elevation of the whole admin panel, change a semantic token. Dark mode overrides the color tokens in the `.dark` block.

## Rules

The `elevation/shadow-tokens` and `elevation/plane-tokens` lint rules (`lint/elevation.ts`) enforce the shadow, plane and scrim rules in class names.

- **Use the lowest plane that works.** Most of a page is canvas and surface.
- **Surfaces don't cast shadows.** Only planes that leave the flow of the page do: raised, popover and elevated.
- **Clip the background of floating planes.** Raised, popover and elevated planes use `bg-clip-padding`, so their semi-transparent border blends with what is behind them, not with their own background.
- **No raw values.** Components never use `shadow-sm`, `shadow-md` or `shadow-lg`, `z-10` or `z-50`, arbitrary z-indexes, or `bg-white dark:bg-mauve-900` for a plane. Use the plane and layer tokens.
- **No z-index inside a portal.** Opening order decides.
- **Isolate local stacking.** `isolate` on the root, `z-1` on the part.
- **An overlay never stands alone.** It always has an elevated plane above it, and closes with it.
- **One scrim at a time.** Mark scrims with `data-overlay`.
- **Raised is temporary.** It lasts while the page moves under the element, then it returns to surface.

## Components

- `Section.Card`, `Table` and `DataList` are surfaces. `Table`'s header is sunken.
- `Menu` and the page size select are popovers.
- `Dialog`, `AlertDialog` and toasts are elevated; Dialog and AlertDialog put an overlay below.
- `Tooltip` is an inverted label without a plane.
- `Table` and `ButtonGroup` isolate their local stacking.
