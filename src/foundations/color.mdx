export const namespaces = {
  bg: '--background-color',

  border: '--border-color',

  outline: '--outline-color',
};

export const Swatch = ({ token, dark }) => {
  const [property, ...rest] = token.split('-');
  const color = `var(${namespaces[property]}-${rest
    .join('-')
    .replace(/\{([^,}]+)[^}]*\}/, '$1')})`;
  // Text meant for a fill is shown on it.
  const pairedFill = {
    'text-base-inverse': 'base-inverse',
    'text-base-on-color': 'action-negative-primary-default',
    'text-action-neutral-on-color': 'action-neutral-primary-default',
  }[token];
  const style =
    property === 'bg'
      ? { background: color }
      : property === 'text'
        ? {
            color,
            ...(pairedFill && {
              background: `var(--background-color-${pairedFill})`,
            }),
          }
        : { borderColor: color, borderWidth: 2 };
  return (
    <div className={dark ? 'dark' : ''}>
      <div
        className="flex size-8 items-center justify-center border border-base-subtle bg-base-canvas type-label-md"
        style={style}
      >
        {property === 'text' ? 'Aa' : ''}
      </div>
    </div>
  );
};

# Color

Color has two layers, after the Color Foundation:

- **Primitives** are Tailwind's palette, with `mauve` as the neutral, the brand's `primary-*` scale and `mauve-tint`. Only `src/theme.css` uses them.
- **Semantic tokens** name a role: `{property}-{role}-{variant}`, such as `text-base-secondary` or `bg-action-negative-primary-hover`. Each has a light and a dark value, chosen so its pairings meet WCAG 2.1 AA. Components use only these.

The property is the utility, so it isn't repeated in the name: the token behind `text-base-primary` is `--text-color-base-primary`, and the one behind `bg-base-canvas` is `--background-color-base-canvas`. In CSS, such as an inline style or an SVG `fill`, use the variable: `var(--background-color-base-surface)`.

Tokens switch with the `.dark` class, so colors never take a `dark:` variant.

When a role has no token, add one to `src/theme.css`, with a light and a dark value, instead of reaching for the palette.

## State layers

Hover and selection are translucent layers, not solid colors. Each one darkens whatever it sits on, so the layers stack: a hovered button on a selected row is still a step darker than the row, on any plane.

<Pair>
  <Layers />
  <Layers dark />
</Pair>

Dark mode layers `mauve-tint`, not white. White and the light mauves are nearly gray, so a thin layer of them turns the dark planes gray. At 15%, the tint turns `mauve-950` into `mauve-900`, and `mauve-900` into `mauve-800`.

Text on a layer loses a little contrast. `text-base-secondary` keeps 4.5:1 even when a row is both selected and hovered; `text-base-tertiary` doesn't, so don't use it on selectable rows.

## Borders

An empty input or checkbox has nothing but its border to show where it is, so WCAG 1.4.11 asks for 3:1 against the colors next to it. `border-base-subtle` reaches 1.24:1 and is only for edges that aren't the sole cue, such as dividers, cards and buttons, whose label shows what they are. `border-base-strong` reaches at least 3.5:1 against the control and the plane it sits on, in both modes.

## Focus

The focus colors mark keyboard focus and nothing else. Use the `focus-ring` utility, which draws `outline-focus-default` in the brand color. A `focus-ring-*` utility changes that color, as `ring-*` does for `ring`, and can sit outside the focus state: `data-invalid:focus-ring-negative` on an invalid field, `focus-ring-neutral` (black, white in dark mode) on a destructive button, where a red or brand ring would blend into the red fill. The default stays a brand color rather than a neutral one: a near-black ring would blend into the near-black primary button. A drop target or a selection outline uses its state token, even when it looks the same.

## Rules

Three lint rules in `@larasell-dev/ui/eslint` enforce this:

- **`larasell/color-tokens`**: no palette colors (`bg-mauve-100`, `text-white`), no colors written out (`bg-[#fff]`) and no palette variables (`var(--color-mauve-300)`), in class lists, inline styles or SVG attributes.
- **`larasell/no-dark-colors`**: no `dark:` variant on a color.
- **`larasell/focus-tokens`**: the focus colors appear only in focus states, and focus states use only the focus colors.
